真正强的机器人应由四部分组成：

```
规则合法性
+
专家策略知识库
+
局面评分系统
+
自动对局调参与评估
```

再高级一些才加入：

```
隐藏手牌采样
+
蒙特卡洛模拟
+
强化学习模型
```



现在系统已经有“牌局记忆”，但它只是**记录层**；如果这些信息没有进入候选动作评分，机器人就等于“记得很多，却不会用”。真正缺的是下面这条链路。

```
公开牌局信息
→ 局面特征提取
→ 专家策略判断
→ 候选动作评分
→ 选择最高分动作
```

局面评分系统本身依赖专家策略知识。评分系统不会凭空知道“什么是好牌”。它必须通过专家策略知识库，把人类经验转化为：

- 哪些局面特征重要；

- 哪些行为应该奖励；

- 哪些行为应该惩罚；

- 不同阶段权重如何变化；

- 哪些规则属于硬约束；

- 哪些策略只是倾向。

专家知识负责告诉系统哪些因素重要，评分系统负责在多个策略冲突时做综合取舍。两者缺一不可，不然机器人不是没脑子，就是脑子里全是互相打架的口诀。

### 一、推荐的机器人决策架构

建议把机器人重构为六个层次。

```
1. 合法动作生成
2. 牌局记忆
3. 局面特征提取
4. 专家策略规则
5. 动作评分
6. 动作选择
```

具体可以设计成：

```
BotDecisionEngine
├── LegalActionGenerator
├── CardMemory
├── SituationAnalyzer
├── ExpertStrategyKnowledgeBase
├── ActionScorer
└── ActionSelector
```

当前系统应该已经有前两项：

```
LegalActionGenerator
CardMemory
```

接下来重点开发：

```
SituationAnalyzer
ExpertStrategyKnowledgeBase
ActionScorer
```



### 二、牌局记忆必须先转成“局面特征”

机器人不能直接拿一大堆已出牌记录去评分。

它应该把原始记录转换成有意义的判断。

例如原始信息：

```
大王已出3张
小王已出4张
对手A剩2张
队友剩5张
队友上一轮出对子
下家连续两次对对子过牌
```

应转换成局面特征：

```
剩余大王数量：1
四王炸风险：0
对手A尾盘威胁：极高
队友接近出完：是
队友可能偏对子牌型：中等概率
下家对子控制力：可能较弱
```

建议建立：

```
interface SituationFeatures {
  phase: "early" | "middle" | "endgame";

  selfRemainingCards: number;
  partnerRemainingCards: number;
  leftOpponentRemainingCards: number;
  rightOpponentRemainingCards: number;

  selfEstimatedTurns: number;
  partnerThreatLevel: number;
  opponentThreatLevel: number;

  remainingBigJokers: number;
  remainingSmallJokers: number;
  remainingLevelCards: number;
  remainingWildcards: number;

  partnerLikelyPatterns: PatternProbability[];
  opponentLikelyPatterns: PatternProbability[];

  currentControlOwner: PlayerId;
  partnerIsLeading: boolean;
  opponentIsLeading: boolean;

  selfRole: "attacker" | "support" | "balanced";
}
```

这一层叫：

```
SituationAnalyzer
```

它的作用是：

> 把“记住了什么”，转换成“现在局面意味着什么”。



### 三、专家策略知识库应该怎样设计

不要只写成一堆口诀。

例如：

```
轻易不接队友牌
顶住上家
吊住下家
谁打谁收
```

这些句子对人有启发，但程序无法直接执行。

每条专家策略应该结构化成：

```
interface ExpertStrategyRule {
  id: string;
  name: string;
  phases: GamePhase[];
  condition: StrategyCondition;
  effect: StrategyEffect;
  priority: number;
  explanation: string;
}
```

例如：

```
{
  id: "avoid-beating-partner",
  name: "轻易不接队友牌",
  phases: ["early", "middle", "endgame"],
  condition: {
    currentLeaderIsPartner: true,
    partnerLikelyToHoldControl: true,
    nextOpponentThreatLevelBelow: 0.7
  },
  effect: {
    actionType: "beat-partner",
    scoreAdjustment: -60
  },
  priority: 80
}
```

再例如：

```
{
  id: "block-opponent-near-finish",
  name: "阻止对手尾盘出完",
  phases: ["endgame"],
  condition: {
    nextOpponentRemainingCardsAtMost: 2
  },
  effect: {
    actionsThatBlockOpponent: +100,
    passAction: -120
  },
  priority: 100
}
```

这就是专家策略知识库。



### 四、评分系统如何使用专家知识

评分系统可以分成三部分：

```
基础价值
+
专家策略修正
+
风险修正
```

形式上：

```
finalScore =
  structuralScore
  + controlScore
  + teamworkScore
  + threatScore
  + memoryScore
  + expertRuleAdjustment
  - destructionPenalty
  - riskPenalty;
```

1. 基础结构评分

衡量动作对自己手牌结构的影响：

```
减少几张牌
减少几手牌
是否拆炸弹
是否拆顺子
是否拆三连对
是否制造新的散牌
```

例如：

```
打出5张顺子：+30
减少1手牌：+20
拆炸弹：-80
拆顺子后产生3个散牌：-50
```

2. 控制权评分

衡量是否能取得或保持先手：

```
能否拿回出牌权
拿回后是否有顺畅后续
是否会把出牌权送给危险对手
```

例如：

```
成功取得控制权：+40
取得控制权后有连续出牌路线：+30
取得控制权但无后续：+5
```

3. 团队协作评分

衡量是否帮助队友：

```
是否压队友
是否给队友送牌
是否帮助队友接风
是否阻止队友完成牌型
```

例如：

```
无意义压队友：-70
队友剩2张时送对子：+80
队友即将接风时抢先手：-60
```

4. 威胁评分

衡量对手是否接近出完：

```
下家剩1张
下家剩2张
对手刚取得先手
对手可能持有尾牌牌型
```

例如：

```
阻止剩1张的对手：+120
对手剩1张时过牌：-150
```

5. 记牌信息评分

这正是当前系统最缺的部分。

例如：

```
所有小王已出
→ 对A的安全度提高

大王只剩1张
→ 王炸风险消失

某玩家多次对对子过牌
→ 出对子给他接的风险降低

某玩家多次主动出单张
→ 其可能仍有散单，吊住下家时提高单牌风险
```

例如专家知识告诉系统：

> 对手只剩2张时，需要重点防对子。

评分系统则把它转化成：

```
出对子让对手可能直接走完：-120
出单张迫使对手拆对：+60
用炸弹阻断：+80
```

所以，没有专家策略知识库，评分系统就只能凭程序员随意设权重。

没有评分系统，专家知识库又会变成大量互相冲突的硬规则。

最合理的是：

> **专家知识决定方向，评分系统解决冲突。**



### 六、建议先做“可解释评分”，不要直接做复杂模拟

你的目标只是达到人类中高级水平，避免明显不合理出牌。

那么暂时不需要：

- 强化学习；

- 深度神经网络；

- 大规模蒙特卡洛；

- 云端大模型；

- 复杂搜索。

先把以下四项做好，水平就会提升很多：

```
手牌结构评分
记牌信息使用
队友与对手威胁判断
专家策略权重
```

我建议先做：

```
Expert Heuristic Bot v1
```

它的决策过程必须可以输出解释：

```
候选动作：对10
总分：72

评分明细：
+25 减少一手牌
+30 可以压制对手
+20 下家剩2张，需要阻拦
-10 消耗较大对子
+7 场上更大对子已大量出现
```

另一个动作：

```
候选动作：炸弹6666
总分：34

评分明细：
+40 取得出牌权
+25 阻止对手
-80 消耗唯一炸弹
+30 对手尾盘威胁高
+19 炸后有顺畅出牌路线
```

这样你一看就知道机器人为什么这么出。



### 七、推荐的具体开发阶段

#### Stage 1：打通记牌到评分的链路

当前最先做的不是继续增加策略，而是确认已有记牌数据能进入决策。

让 Codex 检查：

```
CardMemory
→ SituationAnalyzer
→ ActionScorer
```

每次机器人决策时打印：

```
当前已出大牌
各玩家剩余牌数
各玩家牌型历史
局面阶段
主攻/助攻角色
候选动作评分
最终选择原因
```

如果这些信息没有出现在评分明细中，说明记牌仍然没有真正被使用。



#### Stage 2：建立专家策略目录

先整理20—30条最关键策略，不要一开始写几百条。

优先级最高的策略建议包括：

##### 团队协作

- 不无意义压队友；

- 队友即将出完时优先送牌；

- 队友有控制权时尽量让牌；

- 队友接风时避免抢先手；

- 队友弱时主动承担控制责任。

##### 对手阻拦

- 对手剩1张时重点防单张；

- 对手剩2张时重点防对子；

- 对手剩5张时防顺子和三带二；

- 对手形成冲牌趋势时提高炸弹使用意愿；

- 下家威胁高时优先出高牌。

##### 手牌结构

- 尽量减少总手数；

- 不轻易拆炸弹；

- 不轻易拆完整组合；

- 优先处理弱单张；

- 保留能收回先手的大牌。

##### 记牌算牌

- 王和级牌剩余数量；

- 大牌是否已经走完；

- 某类炸弹是否仍可能存在；

- 各玩家主动出过的牌型；

- 各玩家对哪些牌型频繁过牌。

##### 游戏阶段

- 开局优先整理手牌；

- 中局优先控制和配合；

- 尾局优先精确阻拦和出完。

#### Stage 3：开发动作特征提取器

每个候选动作生成一组特征：

```
interface ActionFeatures {
  cardsPlayed: number;
  turnsReduced: number;

  breaksBomb: boolean;
  breaksStraight: boolean;
  breaksPairChain: boolean;

  gainsControl: boolean;
  likelyKeepsControl: boolean;

  beatsPartner: boolean;
  helpsPartner: boolean;
  blocksOpponent: boolean;

  exposesHighCards: boolean;
  spendsCriticalControlCard: boolean;

  opponentFinishRiskAfterAction: number;
  partnerFinishChanceAfterAction: number;

  memoryBasedSafety: number;
  endgameValue: number;
}
```



#### Stage 4：建立分阶段权重

不要用一套权重覆盖整局。

例如：

```
const weights = {
  early: {
    turnsReduced: 30,
    breaksBomb: -80,
    gainsControl: 20,
    blocksOpponent: 10
  },
  middle: {
    turnsReduced: 20,
    breaksBomb: -60,
    gainsControl: 40,
    helpsPartner: 35
  },
  endgame: {
    turnsReduced: 15,
    breaksBomb: -20,
    blocksOpponent: 100,
    helpsPartner: 80
  }
};
```

尾盘时，阻止对手比保留炸弹更重要。

这就是人类专家“同一原则在不同阶段权重不同”的程序化表达。



#### Stage 5：建立固定牌局测试

不要只跑随机对局。

要准备专家牌例：

```
场景1：队友剩2张，对手剩6张
预期：优先送对子，不压队友

场景2：下家剩1张
预期：避免出小单张

场景3：自己有唯一炸弹，对手剩2张
预期：必要时允许炸

场景4：大王已全部出完
预期：提高高牌冲刺评分
```

每个场景明确：

- 可选动作；

- 推荐动作；

- 不推荐动作；

- 原因；

- 允许的合理备选。

### 八、给 Codex 的任务

```
当前掼蛋机器人已经能够生成合法动作，并记录所有公开出牌、出牌玩家、牌型、过牌记录和各玩家剩余牌数。

现在的问题是，这些记牌信息没有充分参与机器人决策。

请不要重写规则引擎，也不要接入大模型、强化学习或蒙特卡洛模拟。

本阶段目标：
将机器人提升到人类熟练玩家至中高级玩家水平，重点避免明显不合理出牌。

请完成以下工作：

1. 审计当前机器人决策流程
   - 找出 CardMemory、出牌历史和玩家剩余牌数目前在哪里被记录；
   - 说明哪些信息已经进入动作评分；
   - 说明哪些信息仅被记录但没有使用。

2. 设计 SituationAnalyzer
   - 将原始公开信息转换为局面特征；
   - 至少包括游戏阶段、剩余大牌、玩家威胁程度、队友状态、主攻/助攻角色和可能牌型。

3. 设计 ExpertStrategyKnowledgeBase
   - 将专家策略写成结构化规则；
   - 每条规则包含适用阶段、条件、评分修正、例外条件、优先级和解释；
   - 第一版先实现20—30条高价值策略。

4. 设计 ActionFeatureExtractor
   - 为每个合法动作提取结构、控制、配合、威胁、记牌和尾盘相关特征。

5. 重构 ActionScorer
   - 使用“基础评分 + 专家规则修正 + 风险修正”；
   - 支持开局、中局、尾局不同权重；
   - 不使用大量互相嵌套的硬编码 if-else。

6. 增加可解释决策日志
   - 输出每个候选动作的总分；
   - 输出各评分项目；
   - 输出最终选择理由；
   - 支持调试模式开关。

7. 建立固定局面测试
   - 至少设计30个专家策略测试场景；
   - 每个场景包含牌局状态、候选动作、推荐动作和不推荐动作；
   - 测试机器人是否避免明显错误。

8. 保持信息公平
   - 机器人只能读取自己的手牌和公开信息；
   - 不得读取其他玩家真实手牌。

请先输出设计方案和当前代码审计结果，不要立即大规模修改代码。

本阶段先完成架构、代码审计、评分框架和测试框架。

专家策略知识库第一版可以根据现有规则文档 (见"docs/掼蛋规则与说明_1.pdf" 中的"策略制定"、"控牌技术"、"配合原则"、"掼蛋口诀"这些章节）建立草稿，
但不要声称其已经完整，也不要擅自编造复杂的掼蛋专家策略。

请把缺少资料支持的策略标记为：
- 已有规则依据；
- 合理启发式假设；
- 需要专家资料验证。

等补充掼蛋教材、教学文章或实战牌例后，
再完善策略规则和评分权重。
```

### 最终结论

基于你的目标，最优路线不是直接上高级AI，而是先完善：

```
专家策略知识库
+
局面特征提取
+
可解释动作评分
+
固定牌例测试
```

做到这一步，机器人就可以从“会合法出牌”提升到“基本懂牌局”。
