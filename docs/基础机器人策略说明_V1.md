# 基础机器人策略说明 V1

> 本文记录当前 P1 基础机器人的实际启发式策略。它不是掼蛋强制规则，也不宣称是最优策略；其目标是确定、可解释、不会读取隐藏信息，并为后续策略机器人提供可验证基线。

## 1. 可用信息与共同入口

机器人只使用：自己的完整手牌、已公开动作、四家剩余牌数、当前级牌、当前最高牌及规则引擎给出的合法动作。它不读取对手手牌、洗牌 seed 或隐藏估值。

南家点击“提示”时调用**相同**的候选生成和评分函数：提示只高亮建议牌，不会自动出牌；实际提交仍由规则引擎校验。

## 2. 候选动作如何生成

所有候选先经牌型识别和统一规则校验，非法组合不会进入评分。

### 2.1 领出候选

机器人枚举：

- 每一张单牌；
- 完整同点数组（对子、三张、4–10 张普通炸弹）；
- 不拆组的三带二：恰好三张的同点数组，搭配恰好一对的同点数组；
- 不使用逢人配补齐的自然顺子。

这是一套有意收窄的基础候选集：当前不会主动枚举所有三连对、钢板、含逢人配的复杂组合、自然同花顺或四王炸。规则引擎支持这些合法牌型；“未枚举”只是当前机器人能力边界。

领出时，炸弹被视为保留牌：只要手中仍存在非炸弹牌，机器人不会主动领出炸弹；只有余牌全部为炸弹，或某手炸弹正好是全部余牌时，才允许领出炸弹。

### 2.2 跟牌候选

桌面存在最高牌时，机器人枚举：

- 与桌面最高牌相同张数的全部手牌组合；
- 每一组完整的 4 张及以上同点数普通炸弹。

因此它可以跟对子、三张、三带二、顺子等，而不只会跟单张；炸弹也可以压制普通牌型或用更大的完整炸弹压制较小炸弹。候选集中同时包含“过牌”（领出时没有过牌）。

## 3. 首次出牌（领出）优先级

机器人选择总分最低的候选。其主要偏好由强到弱如下。

1. **不拆完整同点数组。** 从一组已有两张或以上的同点数牌中只抽取部分牌，受到极高惩罚。例如手有 `999` 时，单出一张 9 通常远差于完整走 `999`。
2. **低位短牌须有同型回收牌。** 对低单、低对、低三张和低三带二，只有在余牌中仍有足以回收牌权的同型高牌时才保持优先；否则显著降权。顺子和更长牌型不受该门槛限制；炸弹不计作回收牌。
3. **小牌优先。** 在拆组风险与回收条件相同的情况下，比较键更小的候选优先，目的是先处理未来更难走的小牌。
4. **多出牌优先。** 在前述条件相同的情况下，优先张数更多的候选，以更快减少手牌数量。
5. **非残局不低配红桃级牌。** 若红桃级牌直接作为本级牌即可使用，不会为了刚好压住小牌而把它解释为更低点数。
6. **确定性并列裁决。** 所有评分仍相同则按动作 JSON 的字典序选择，确保同局面结果可复现。

### 3.1 回收牌门槛

这里的“回收牌”指余牌中可用于同型夺回牌权的高牌，具体为：

| 拟领出的牌型 | 低位时要求的余牌回收牌 |
| --- | --- |
| 单张 | 至少一张 A、级牌、小王或大王 |
| 对子 | 至少一对 K、A 或级牌 |
| 三张 | 至少一组 J、Q、K、A 或级牌三张 |
| 三带二 | 至少仍可组成一手主三张为 J、Q、K、A 或级牌的完整三带二 |
| 顺子及更长牌型 | 不设回收牌门槛 |

当拟出牌本身已达到上述高位（单张 A/级牌及以上、对子 K/级牌及以上、三张或三带二主组 J/级牌及以上）时，也不再因缺少余牌回收而降权。

## 4. 接牌与过牌策略

### 4.1 队友正在压住

若当前最高牌属于对家，且“过牌”合法，机器人以极高优先级过牌，不无意义地压住队友。

### 4.2 对手正在压住

若当前最高牌属于对手，只要存在合法压制动作，机器人会强烈优先接牌；只有没有合法压制动作时才过牌。

### 4.3 残局

任意一家公开剩余手牌数不超过 1 张即视为残局临界：

- “过牌”的代价提高，机器人更倾向夺回牌权或拦截；
- 红桃级牌允许低配，以保留残局中拦截或放对家的空间。

### 4.4 多个压制动作的取舍

在决定接牌时，评分依次偏好：

1. 不拆对子、三张、炸弹等完整同点数组；
2. 不低配红桃级牌（非残局）；
3. 少出牌；
4. 使用比较键较小、刚好足够压住的牌；
5. 用固定字典序打破完全相同的情况。

这与领出策略不同：接牌的首要目标是以尽可能低的代价夺回或阻断牌权，而不是尽量一次走更多牌。

## 5. 已知边界与改进方向

本机器人不是搜索型或算牌型 AI：

- 不根据公开出牌精确推断剩余牌分布；
- 不做多步搜索、概率评估或对家协同规划；
- 不主动枚举全部复杂连牌、逢人配组合、同花顺和四王炸；
- 除“队友压住时优先不过牌”外，没有更深入的放对家或拦截配合；
- 不根据牌局阶段动态调整回收门槛，残局规则仅使用“任意一家 ≤1 张”的简单阈值。

后续提升建议是：牌组结构识别、公开记牌概率、对家协同、完整炸弹/同花顺枚举、残局搜索和可配置难度。上述改进应独立迭代，不能改变 `掼蛋规则(被采用)_V1.md` 中的规则裁决。
