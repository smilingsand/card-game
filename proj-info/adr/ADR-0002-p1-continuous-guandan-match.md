# ADR-0002：P1 连续多局掼蛋赛局状态与进贡事件

- 状态：已接受；第 2 条已被 ADR-0012 修订
- 日期：2026-07-14
- 决策人：产品负责人

## 背景

现有 P1 桌面只运行一局，`settlement.ts` 的纯结算函数未接入牌桌。产品确认要支持连续多局：双方独立等级、单下/双下进贡与抗贡；南家进贡和还贡均需手动选择。本文最初将级牌与先出方绑定，后续已由 ADR-0012 更正。

## 决策

1. 赛局状态保存双方等级、局号、上一局完成顺序、当前进贡阶段、公开贡牌/抗贡证明与当前局先出方；单局 `TurnState` 不承载这些赛局事实。
2. 每局创建 `TableGame` 时注入该局级牌与先出方。**历史决定：级牌为先出方所属队等级；该部分已由 ADR-0012 改为上一局头游方升级后的等级。**首局双方等级均为 2，南家先出。
3. 完成一局后仅头游所在队升级：双上升 3、头三升 2、头末升 1；另一队等级不变。打 A 双上仍结束整场。
4. 进贡、还贡与抗贡使用版本化赛局事件记录实体牌 ID、方向、公开贡牌与证明；牌交换后才创建下一局。南家作为进贡者或还贡者必须手动提交，机器人按确定性合法策略提交。
5. 存档升级 `rulesVersion` 与 `saveSchemaVersion`；旧单局存档不得静默以连续赛局规则恢复。

## 后果

- 规则核心继续保持纯 TypeScript，UI 只提交赛局动作。
- 左上角记分牌与贡牌提示、完成顺序后的下一局提示均只读取赛局公开状态。
- 需要为双方等级、单双下、抗贡、实体牌交换、恢复和 UI 状态补充固定牌例。
