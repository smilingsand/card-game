# ADR-0017：P2.5 Expert FollowUp 筛选性能合同（提案）

- 状态：proposed（待产品确认；不得据此修改生产代码）
- 日期：2026-07-18
- 决策人：待确认
- 关联：ADR-0008（BotView 信息边界）、ADR-0016（P2.5 专家机器人合同与性能预算）、P2.5-16

## 背景与问题

当前 expert 决策保留全部合法语义候选，并为每个候选执行完整的动作后分析与 `FollowUpPlanner`。seed=0 的实测表明，完整 `FollowUpPlanner` 占一次冷缓存决策约 89%--93% 的时间；不能通过扩大 LRU、Worker、墙钟超时、裁剪合法动作或以 normal 结果代替 expert 解决。

本提案重新界定 FollowUp 的语义：它是对少数“基础评分竞争者”的深度路线证据，而不是每个合法候选都必须具备的评分分项。合法性、基础评分和可解释候选列表仍对全部候选完整执行。

## 拟议合同

### 1. 两阶段 expert 评分

对每个由 A 层产生的、语义上不同的 candidate（严格等价 alias 按 ADR-0016 的 canonical 规则合并）均执行：

1. 完整合法性确认与稳定候选排序；
2. `baseScore`：当前牌型/比较键/炸弹与逢人配成本、公开局面、控制资源、规则命中和共享物理动作后的手牌质量；
3. 完整基础解释：评分分项、命中规则、canonical/alias 信息、稳定 candidate key。

随后按确定性 `followUpSelectionKey` 从全部 candidate 中选出有限集合，**仅该集合**执行完整 `FollowUpPlanner`。未入选 candidate 不是被删除或假装完成 FollowUp；其解释必须标记 `followUpStatus: "not_evaluated"`、未入选原因、稳定排名及适用的默认 FollowUp 分值。

最终分数定义为：

```text
finalScore = baseScore + followUpScore
```

- `evaluated`：`followUpScore` 来自完整、可重放的 FollowUp 结果；
- `not_evaluated`：`followUpScore` 为 profile 明确定义的 `0`，并在解释中声明“未纳入深度路线评估”。

这是一项**语义合同变更**：不再承诺“每个合法候选都有完整 FollowUp”。它不宣称与旧的全候选 FollowUp 分数或动作逐字段一致；它承诺同一输入与同一 profile/version 下，新合同结果逐字段确定且可回放。

### 2. 确定性、可解释、可回放的筛选

`followUpSelectionKey` 固定为：

```text
baseScore descending
→ mandatoryReason priority ascending
→ canonical physical action key ascending
→ semantic interpretation key ascending
```

先纳入所有满足以下客观条件的 mandatory candidate，再以该排序补足预算：

- `finish_now`：动作后己方剩余手牌为零；
- `must_beat`：当前公开牌权下该语义候选可压制，且公开威胁等级为 critical；
- `partner_finish_setup`：公开信息表明队友下一手可能出完，且候选不改变该公开判断。

mandatory candidate 本身同样受硬上限保护；若数量超过硬上限，按同一 key 选取并在 explanation 中报告 `mandatory_overflow`。不得按运行时间、随机数、缓存命中、机器性能或候选生成顺序改变集合。

每个决策必须记录：候选总数、基础评分排序、入选集合、每个入选/未入选理由、profile/version、预算及最终动作。失败 seed 使用该快照即可重放。

### 3. 推荐 profile 参数（待确认）

| profile | `followUpEvaluationCandidateCount.default` | `max` | 用途 |
| --- | ---: | ---: | --- |
| normal | 不适用 | 不适用 | 保持既有 legacy normal path，零行为变更 |
| expert | 32 | 32 | P2.5-16 的推荐生产候选预算；所有合法候选先完成 baseScore |
| experimental | 64 | 64 | 质量对照与校准；不能作为 normal 或 expert 的静默回退 |
| `experimental-full-follow-up` | 全部 semantic candidates | 全部 | 仅基准/差分对照，不设为默认生产入口 |

`FollowUpPlanner` 内部既有“合法领出 Top-10”合同仍独立存在；本提案只新增“哪些顶层 candidate 进入完整 FollowUp”的预算，不改变其 10 个已入选领出候选的计算语义。推荐先以 32/64 验证；任何调整均须提高/降低 profile 版本，而非运行期自适应。

### 4. 明确不做的事

- 不裁剪任何规则合法、语义不同的顶层动作；
- 不扩大 LRU 以掩盖成本，不以 Worker 掩盖单次决策 P95；
- 不使用墙钟超时、动态降深或“当前最佳”提前返回；
- 不改变 normal profile、规则权重、tie-break、合法动作生成或 BotView 信息边界；
- 不把未入选候选称作已完成完整 FollowUp，也不从 `DecisionExplanation` 删除它。

## 验收与对照

实施前先冻结 `experimental-full-follow-up` 作为参考 profile。实施后必须证明：

1. 所有固定牌例、随机局面与失败 seed 的合法候选集合、canonical/alias 关系和 baseScore 逐字段可复现；
2. 同一新 profile 输入的完整 `DecisionFingerprint`（含入选集合及未入选原因）逐字段相同；
3. normal 路径调用与回归输出不变；
4. expert 不读取隐藏手牌，且没有 fallback 到 normal；
5. 以 full-follow-up 对照 profile 报告动作差异率、差异牌例和九项指标变化；差异是待审查的数据，不可被静默接受；
6. 分阶段运行 100、500、2,500、10,000 局；分别报告冷/暖缓存单次平均、P50/P95/P99、最慢决策、模块占比、候选与入选数量分布、缓存/内存与失败 seed。

性能预算仍为 expert 单次平均 <=100ms、P95 <=250ms；批量吞吐仅单独报告，不替代浏览器真实交互的单次 P95。若预算未达成，P2.5-16 继续暂停并提交可重放慢例与模块剖析，不再自行降低候选预算。

## 实施顺序（确认后）

1. 先写 selection/fingerprint/normal-isolation/hidden-information 测试；
2. 增加版本化 profile 配置和解释字段，再接入两阶段评分；
3. 用 full-follow-up experimental 对照完成固定 seed=0 与随机/失败 seed 复放；
4. 依次通过 100、500、2,500、10,000 局门禁，才可更新 P2.5-16 验收状态。

在本 ADR 被明确接受前，P2.5-16 保持暂停，不得修改生产代码或启动 P2.5-17。
