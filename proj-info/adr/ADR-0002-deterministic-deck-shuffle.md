# ADR-0002：确定性洗牌与发牌约定

- 状态：已接受
- 日期：2026-07-13
- 决策人：开发团队

## 背景

P1-03 需要让同一个 seed 可重放两副牌的洗牌和四人发牌结果。随机数发生器与洗牌过程一旦进入事件重放和存档，是不可逆的兼容性选择。

## 决策

1. seed 使用 `0` 至 `4_294_967_295` 的无符号 32 位整数；其他值在入口被拒绝。
2. 伪随机数发生器固定为公开、无状态外部依赖的 Mulberry32 变体，每次调用产出区间 `[0, 1)` 内的 JavaScript number。
3. 洗牌固定为从数组尾端到索引 1 的 Fisher-Yates：每一步选择 `floor(random() * (index + 1))` 并交换。输入牌组不被修改。
4. 四人发牌的座位顺序固定为 `east`、`south`、`west`、`north`；按洗牌后数组的顺序循环发牌。因此，108 张两副牌会让每个座位得到 27 张。
5. 实体牌 ID 格式固定为 `deck-{1-based deck number}-{suit}-{rank}`。ID 是物理身份，不能用花色和点数替代；任何重复或缺失 ID 都使守恒校验失败。

## 后果

- 不得使用 `Math.random()`、时间或浏览器 API 参与洗牌或发牌。
- 变更 PRNG、洗牌步骤、座位顺序或 ID 格式时，必须新增 ADR，并为受影响的存档/事件格式引入新版本，不能静默重放旧记录。
- 此算法用于可重放性，不是密码学安全随机数；P3 若需要对抗性随机性，必须另行做服务端权威随机数 ADR。
