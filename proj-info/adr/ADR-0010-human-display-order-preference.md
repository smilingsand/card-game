# ADR-0010：人类手牌显示顺序作为本地 UI 偏好

- 状态：已接受
- 日期：2026-07-13
- 决策人：开发团队

## 背景

P1-15B 允许真人按自己的记牌习惯整理手牌，并要求刷新后恢复。此顺序必须进入本地存档，但不能污染 P1-04 的可重放规则事实。

## 决策

1. 人类显示顺序是仅属于当前浏览器 UI 的偏好数据，以唯一实体牌 ID 的有序数组 `humanDisplayOrder` 保存；它不属于 `TurnState`、`TableGame`、事件流或快照状态。
2. 首次没有有效偏好时，UI 用纯函数根据当前手牌的真实牌面和级牌生成确定性易读顺序：同点数相邻，普通点数、级牌与大小王按固定可读优先级排列。拖拽只重排该数组。
3. 出牌、机器人动作或恢复后，偏好与当前真人手牌取交集；已出牌 ID 被移除，新出现的 ID 按默认顺序稳定追加。规则 action、`action.applied` 事件及机器人 `BotView` 均不得携带或读取该字段。
4. `saveSchemaVersion=2` 在既有规则流/快照之外增加该可选字段。恢复同时接受 P1-14 的 `saveSchemaVersion=1`，并回退到默认排序；v2 中缺失、重复、非字符串或不属于手牌的 ID 视为无有效偏好，同样回退而不拒绝可重放的旧对局。其余规则、事件及快照兼容规则仍遵循 ADR-0003。

## 后果

- 显示偏好可以随本地会话保存和恢复，却无法改变 seed + events 的重放结果。
- 未来若增加多人或多设备同步，显示偏好仍需保持在个人视图/客户端边界，不能发送到权威规则服务。
