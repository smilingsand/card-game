# ADR-0034：P4 显式退出房间与继续牌局

- 状态：accepted
- 日期：2026-07-30
- 决策者：产品负责人
- 取代：ADR-0030 中“已开局房主断线不得关闭房间”的主动关闭限制；被动断线、心跳和临时托管规则仍由 ADR-0033 与 ADR-0030 约束。

## 决策

应用默认进入首页，用户在首页显式选择单人或多人游戏。单人游戏的“退出”只卸载本地单人界面并返回首页，不清除 IndexedDB 存档。

多人牌桌的“退出”不向服务端提交关闭或重开命令。它只切换该浏览器到已开局房间大厅，保留 `roomId`、WebSocket 和权威牌局；大厅显示“继续游戏”，点击后必须重新读取该匿名身份的 `game-view` 个人投影，不能复用旧手牌、旧合法动作或客户端牌局状态。

多人大厅右上角“退出”是唯一的离房入口：

- 房主退出：请求权威 `close`。Room 取消 bot task 与 alarm，通知 Realtime Room 发送 `roomClosed` 并关闭所有 socket，销毁 Room、Authority 和 Realtime 的本地持久记录。收到通知的其他客户端返回首页。
- 非房主退出：只提交自身 `presence: connected=false`，并卸载本地 WebSocket/个人投影后返回首页。房间、其他玩家和既有断线托管规则不受影响。

房主主动关闭是明确的产品操作，因此即使牌局已开始也被允许；这与被动断线不同，不等待房主保留期或转让。

## 后果

- “继续游戏”不会重开、重新发牌或改变机器人已经执行的权威动作；若关闭或过期发生在大厅期间，读取失败或 `roomClosed` 通知必须返回首页。
- 客户端以 `tableExited` 本地标记拒绝在退出牌桌后的异步机器人/Realtime 投影覆盖大厅；恢复前的旧请求不得重新展示牌桌。
- `close` 仅能由 `meta.ownerId` 调用；Authority 再次校验同一 owner。非房主不能删除房间或其他玩家的数据。
- 本地开发监听 5173 的 Vite 绑定 `0.0.0.0` 以支持局域网浏览器；后端 8788 继续仅限 loopback，通过 Vite 代理访问。
