# ADR-0018：P2.5 Expert baseScore 两阶段性能合同

- 状态：accepted
- 日期：2026-07-18
- 决策人：产品负责人
- 关联：ADR-0008（BotView 信息边界）、ADR-0016（专家决策合同）、ADR-0017（FollowUp 筛选合同）、P2.5-16

## 背景

ADR-0017 已将完整 FollowUp 限于确定性入围候选，但 seed=0 的真实 expert 决策仍对 3,300 个 physical action 执行完整 `PostActionHandEvaluator`。冷缓存 23.10s 中 PostAction 占 16.14s（69.8%）；100 局门禁无法在 300 秒内完成。

本 ADR 将完整 PostAction、HandPlan 重组、ControlResourceEvaluator 与 FollowUp 共同定义为“深度候选评估”。它们只对轻量 baseScore 确定性入围的候选执行。所有合法语义候选仍保留、评分、解释和可回放。

## 合同

### 1. 全量轻量阶段

每个语义上不同的 canonical candidate（严格等价 alias 仍按 ADR-0016 合并）必须完成：

- 规则层合法性确认及稳定 candidate key；
- `lightBaseScore`：当前手牌结构、当前整手 HandPlan、当前公开局面、牌型/比较键/炸弹/逢人配机会成本、可在不模拟移除牌后手牌的规则命中与稳定 tie-break；
- 基础解释、候选排序与未入围原因。

该阶段不得调用 `PostActionHandEvaluator`、动作后 `HandPlan` 重组、`ControlResourceEvaluator` 或 `FollowUpPlanner`；不得读取隐藏信息、墙钟、缓存命中或机器性能。

### 2. 深度入围与选择资格

按下列稳定 key 从所有语义 candidate 中选择深度入围集合：

```text
lightBaseScore descending
→ mandatoryReason priority ascending
→ canonical physical action key ascending
→ semantic interpretation key ascending
```

mandatory 优先级固定为：`finish_now` → `must_beat` → `partner_finish_setup`。mandatory 先入围；只有其数量超过 max 时才按上述优先级和 stable key 截断，记录 `mandatory_overflow`。

仅入围集合依次执行：

1. `PostActionHandEvaluator`；
2. 动作后 `HandPlan` 重组；
3. `ControlResourceEvaluator`；
4. ADR-0017 的完整 FollowUp 筛选与 `FollowUpPlanner`；
5. 完整 expert 规则、评分与 `DecisionExplanation`。

最终动作只能从 `postActionStatus: "completed"` 且 `followUpStatus: "completed"` 的 candidate 中选择。未入围 candidate 必须保留：

```text
postActionStatus: "not_evaluated"
followUpStatus: "not_evaluated"
not_finally_eligible: true
lightBaseScore
screeningReason
```

未入围 candidate 不是非法、被删除或被 normal 替代；它们只是依此合同不具备最终选择资格。

### 3. 冻结预算

| profile/configuration | 深度 PostAction 默认 / max | 完整 FollowUp 默认 / max | 用途 |
| --- | ---: | ---: | --- |
| normal | 不适用 | 不适用 | 原有 legacy normal path，零行为变更 |
| expert | 64 / 96 | 32 / 64 | 正式显式 expert 评估；mandatory 可扩展至 max |
| experimental | 128 / 192 | 64 / 64 | 校准与质量对照，不能回退 normal |
| `experimental-full-post-action` | 全部 / 全部 | 全部 / 全部 | 仅差分、回归和基准对照，不作为生产入口 |

预算是版本化 profile/config 的一部分；不得运行期自适应，不得为性能降低已冻结数值。深度 PostAction 入围不改变 ADR-0017 的 FollowUp 入围排序与 mandatory 规则。

### 4. 差分、回滚与验收

实现前冻结 `experimental-full-post-action` 对照配置。实现后：

1. seed=0 先验证全量轻量候选集合、key、lightBaseScore、入围集合和解释逐字段确定；
2. 新 expert profile 对相同 BotView 的完整 `DecisionFingerprint` 必须逐字段可复现；
3. 对照 profile 必须可重放完整 PostAction/FollowUp；报告与新 expert 的最终动作差异、九项指标差异和具体牌例，差异不得静默接受；
4. normal 调用路径与输出不变，expert 不读取隐藏手牌且不得 fallback；
5. 依次运行固定牌例与 100、500、2,500、10,000 局门禁。性能仍分别报告浏览器单次冷/暖 P50/P95/P99 与批量吞吐；后者不能替代前者。

回滚为显式切换 normal 或 `experimental-full-post-action` 对照配置；不得把 expert 静默降级为 normal。

## 禁止项

不得裁剪规则合法动作、按墙钟返回当前最佳、依赖 Worker 掩盖单次 P95、动态降低预算、扩大 LRU 以掩盖成本，或改变规则权重、评分精度和稳定 tie-break。

P2.5-17 在 P2.5-16 所有门禁通过前不得启动。
