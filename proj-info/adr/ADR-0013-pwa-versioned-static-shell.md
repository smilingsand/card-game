# ADR-0013：PWA 版本化静态离线壳

- 状态：已接受
- 日期：2026-07-15
- 决策人：产品负责人

## 背景

P2 需要让已安装的单机客户端在断网后仍能启动，同时不能让旧的应用壳在规则或存档版本变更后被误认为是当前版本。浏览器 Cache Storage 与 IndexedDB 的生命周期不同：前者适合可替换的静态资源，后者保存版本化的牌局事件流和快照。若 Service Worker 将存档响应、运行时 API 或不带构建版本的页面混入静态缓存，升级时可能产生旧规则代码、页面和存档的混搭。

## 决策

1. Service Worker 仅预缓存由当前 Vite 构建产生的静态应用壳：入口 HTML、带内容哈希的 JavaScript/CSS 资源、manifest 和图标。缓存名同时包含当前 `rulesVersion` 与构建版本。
2. 导航请求在线时采用 network-first；断网时只回退到同一版本的离线壳。静态资源使用 cache-first，且只接受同源成功响应。
3. 新 Service Worker 安装后通知正在运行的旧页面；用户确认“更新”后才 `skipWaiting`，激活时删除所有非当前版本的本应用缓存，并重新加载页面。
4. Service Worker 不读取、不写入、不缓存 IndexedDB、事件流、快照、用户操作或任何牌局数据。存档继续完全由既有 `StorageBoundary` 管理，并由 `rulesVersion` / schema 校验拒绝不兼容数据。
5. 每次规则版本变更必须同步改变离线壳缓存版本；仅普通静态构建变更则改变构建版本。两者均使旧缓存不能充当新版本的应用壳。

## 后果

- 离线首次启动依赖至少成功完成过一次同版本在线加载和 Service Worker 安装；不能承诺从未联网的安装包可运行。
- 更新提示不是牌局规则的一部分，不写入事件流、快照或 IndexedDB。
- 当前实现不引入第三方 PWA 插件：Vite 构建阶段生成资源清单和 Service Worker，以便缓存清单与实际带哈希的构建产物严格一致。
