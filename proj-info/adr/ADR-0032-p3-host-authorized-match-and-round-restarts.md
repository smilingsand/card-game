# ADR-0032：P3 房主重开赛局与重开本局

- 状态：accepted
- 日期：2026-07-27
- 决策者：产品负责人

## 决策

多人房间在已开始状态保留房间 ID、邀请凭据、逻辑座位、`controllerSubjectId` 与当前房主。只有当前房主可以请求以下权威操作；Worker 与 Room 必须在到达 Authority 前校验调用者仍是当前房主，前端禁用仅为体验，不构成授权。

- **重新开赛**：不要求任何玩家重新准备。Authority 生成新的 `gameId` 与新的 256 位 CSPRNG seed，清除整场比赛的动作命令、事件和快照，将双方等级恢复为 2，并以权威首出者立即开始新首局。原动作命令因其旧事件序号而被拒绝，不能污染新赛局。
- **重开本局**：不要求任何玩家重新准备。Authority 保留上一局已结算的比赛状态（包括等级、完成顺序、级牌及由其计算的进贡/还贡状态），但为当前局生成新的 `gameId` 与新的 256 位 CSPRNG round seed，并从当前局发牌开始重新计算贡牌与首出者。它不改变房间、座位、控制权或房主。旧动作命令不再命中旧 ACK，必须通过当前权威事件序号校验。

两项操作均在 Durable Object 内串行执行，携带 `clientCommandId` 与期望事件序号；成功后广播仅含 room 变更的实时失效通知，各客户端重新读取自己的个人投影。seed、完整状态、其他手牌与机器人隐藏评估不得出现在 API、WebSocket、日志或客户端状态中。

## 后果

- Room 路由新增受保护的重开赛局/本局入口；Authority 新增内部重开操作与重放材料，所有变化仍由 `@card-game/guandan-core` 生成。
- “重开本局”保留权威可重放事件材料以复原比赛状态；其新 round seed 独立加密保存。每次重开均清除旧客户端动作命令，仅保存本次重开命令的幂等 ACK。
- 手动手牌排序和横/竖排仅是客户端个人显示偏好，不进入 Room、Authority、事件或他人投影。
