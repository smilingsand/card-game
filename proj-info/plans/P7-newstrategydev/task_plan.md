# P7：基于公开信息的 normal-vNext 策略升级计划

## 目标

在不恢复 P2.5 expert/master 路线、不改变 `guandan-v5` 规则、也不扩大机器人可见信息的前提下，分步将上游项目中可取的协同、控牌、炸弹经济和残局路线评估思想，重构为 `@card-game/guandan-core` 内可重放、可解释、可验证的 normal-vNext 策略能力。

## 范围与硬约束

- 产品策略仍只有 `normal-vNext`；不增加 easy/medium/hard/master UI 或配置。
- 不复制上游 `guandan-windows` 策略源码；仅将策略思想以本项目的领域模型重新实现。
- 策略只接收 `BotView`：己方手牌、公开事实、公开剩余张数、当前桌面状态和规则层生成的合法动作；不得读取对手手牌、洗牌 seed、未发牌或隐藏评估。
- 规则识别、比较和合法动作只能来自 `packages/guandan-core`；策略层不得重建它们。
- 同一 `BotView` 必须产生同一动作和解释；不使用 `Math.random()`、时钟截止或模块级可变记忆。
- 每个任务都须先增加固定牌例或失败回归，再实现最小改动；每个任务独立提交。
- P2.5 的 expert/master 路线保持撤销。任何未来恢复提议必须先新增 ADR，且不属于本计划。

## 当前阶段

P7-02（可解释的候选动作评分框架）已完成：normal-vNext 对规则层合法候选的响应排序已
统一为可复核分项；未加入搜索、概率模型或新产品难度。多 seed 长运行仍受当前受控执行环境
限制；它不是 P7-00 验收替代品，将作为 P7-05 的收敛门槛重新执行。

## 分阶段任务

### P7-00：立项与基线冻结

- [ ] 新增 ADR：记录策略目标、信息边界、确定性和“不恢复 P2.5”的决定。
- [ ] 新增 P7 阶段 README、任务表、测试矩阵和发布记录模板；不改写历史 P2/P2.5 证据。
- [ ] 为当前 `normal-vNext` 建立固定基线：策略牌例集、固定 seed 自动对局结果、决策耗时与候选数统计。
- [ ] 验收：基线可由相同提交和 seed 重放；P7 文档明确唯一产品策略仍为 normal-vNext。
- **状态：** accepted

### P7-01：公开观察模型与安全投影

- [ ] 设计并实现只读 `StrategyObservation`：已公开出牌的牌面/牌型统计、各座剩余张数、最近动作与轮次信号、己方/队友/对手位置关系。
- [ ] 通过版本化公共事件或投影提供已公开牌面；不能仅给不可解析的 card ID，也不能随之暴露牌堆顺序、seed 或未出牌。
- [ ] 定义赛局只读上下文：双方等级、是否 A 关、进贡/抗贡及首出来源；不改变规则状态或存档语义。
- [ ] 提供从公开事件按 sequence 纯函数重建 observation 的入口；不使用模块级 `Map` 缓存作为事实来源。
- [ ] 验收：四座信息泄露测试、事件重放等价测试、旧存档/投影兼容测试均通过。
- **状态：** accepted

### P7-02：可解释的候选动作评分框架

- [ ] 将现有结构破坏、控制资源、红桃级牌机会成本、手牌卸载收益和拦截收益归一为稳定的评分分项。
- [ ] 为每项分数提供可读 reason / breakdown；策略只对规则层 `legalActions` 排序，并以固定 tie-break 选择。
- [ ] 增加机会成本牌例：不拆炸弹/三张/连续结构、非必要不使用红桃级牌、较小足够压制优先。
- [ ] 验收：所有固定牌例动作合法且确定；解释分项之和与最终排序可复核。
- **状态：** accepted

### P7-03：协同、公开威胁与炸弹经济

- [ ] 基于公开座位、剩余张数和最近公开动作实现队友持权让牌、队友临门喂牌、下家尾局阻断。
- [ ] 引入公开记牌驱动的控制资源风险指标：仅根据己方牌、已公开牌和完整牌组组成估计未见资源，不假定分布在某一对手手中。
- [ ] 定义主动炸弹的正向条件：保队友、阻断高风险对手、炸后有确定的续控/收尾收益；其余情况施加可解释惩罚。
- [ ] 验收：协同/拦截/炸弹固定牌例；四座 BotView 无隐藏信息属性与运行时访问测试。
- **状态：** pending

### P7-04：确定性手牌路线评估

- [ ] 实现仅基于己方剩余手牌的有限深度路线估计：候选动作后可出手数、死单/死对、自然复合结构和控制资源保留。
- [ ] 采用固定候选上限、固定节点/深度预算与稳定排序；不采用 wall-clock budget，也不调用对手手牌的合法动作生成。
- [ ] 在残局优先识别一手/两手可完成路线，并与队友/对手公开剩余张数协调。
- [ ] 验收：路线选择固定牌例、同输入多次决策一致性、浏览器与 Node 结果一致、性能门槛通过。
- **状态：** pending

### P7-05：回归评估、策略收敛与发布

- [ ] 建立策略基准命令：固定 seed 对局、决策分布、动作耗时分位数、非法动作/超时/循环统计；不将胜率作为唯一质量证据。
- [ ] 对比 P7-00 基线，人工审阅代表性决策解释与不利回归；只接受有明确牌例理由的行为变化。
- [ ] 完成格式化、typecheck、lint、单测、自动对局、前端/多人个人投影 E2E 冒烟；按阶段要求完成 Preview 和 Production 验收。
- [ ] 更新阶段文档、release、风险与回滚目标；若上线结果不达标，回退至 P7-00 策略版本。
- **状态：** pending

## 决策与待确认项

| 决策 | 理由 |
| --- | --- |
| 先 observation，后策略 | 记牌和赛局策略必须有可审计的公开事实输入。 |
| 搜索只评估己方手牌路线 | 在 P3/P4 个人投影下安全、确定，且避免上游窥牌实现。 |
| 保持 normal-vNext 单一产品档位 | 符合当前产品边界和用户要求，避免恢复 P2.5。 |
| 不以短样本胜率验收 | 策略回归必须同时看固定牌例、合法性、解释与性能。 |

## 风险与退出条件

| 风险 | 控制措施 |
| --- | --- |
| 公共事件缺少公开牌面 | 在 P7-01 先设计兼容投影与旧事件处理，未通过前不开始记牌策略。 |
| 候选组合爆炸 | 始终从规则层候选集开始，并设固定节点/候选上限和性能测试。 |
| 启发式互相抵消 | 每项评分独立暴露、牌例驱动、小步提交和基线差异审阅。 |
| 多人投影泄露 | P7-01/P7-03 必做四座投影和静态 import/字段边界测试。 |
| 策略变弱或不可解释 | P7-00 可独立回退；未获得固定牌例和人工审阅证据不得发布。 |
