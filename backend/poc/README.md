# P3-01 Durable Object 本地 POC

此目录是可删除、非生产的选型验证，不是 P3 后端工程。它使用 Miniflare 在本机执行一个等价的 SQLite Durable Object；不读取云凭证、不创建 Cloudflare 资源，也不与任何网络服务建立连接。

## 覆盖范围

`four-client-durable-object.poc.mjs` 将四个模拟客户端发往同一个 Durable Object，持久化连接状态和事件计数；随后断开两名客户端，销毁运行时以模拟对象休眠后的冷启动，并以同一持久化目录创建新运行时。重建后读取持久状态，再让两名客户端重连。

执行：

```powershell
npm.cmd test
npm.cmd run measure
```

2026-07-23 的本机测量结果：

| 口径                          | 结果     |
| ----------------------------- | -------- |
| 并发模拟客户端数              | 4        |
| 断连后 / 冷启动恢复后客户端数 | 2 / 2    |
| 重连后客户端数                | 4        |
| 事件数                        | 8        |
| 四客户端连接批次耗时          | 344.41ms |
| 两客户端重连批次耗时          | 86.33ms  |

耗时是本机 Miniflare 中 `Promise.all` 批次的墙钟时间，不代表线上网络延迟或容量上限。容量证据是 Cloudflare 文档所述每个 Durable Object 最多 32,768 个休眠 WebSocket；本 POC 仅验证本项目所需的四席语义。当前开发、测试和早期公网 MVP 均使用 Workers Free，不购买 Paid；真实的 Free 配额、连接规模和生产 RPO/RTO 仍由 P3-10/P3-12 以部署当日官方口径进行验收。P3-12 前不得创建云资源；届时必须先等待用户注册 Free 账号并在其本机完成 `npx wrangler login` 浏览器授权。

## 边界

- 这是 HTTP 请求模拟，不是最终的浏览器 WebSocket 协议；`p3-ws-v1` 的线序、ACK 和缺口恢复仍由 P3-06 实现。
- 对象重建用 `dispose()` + 同一持久化目录模拟，因此验证了权威状态不依赖进程内存；真实 Worker 的休眠/部署重启处理仍必须由 P3-04 回归测试覆盖。
- 临时持久化目录创建在系统临时目录，并在每次运行后删除。
